# Ходы с независимым начислением очков: требования и тест-раны

Статус: **реализовано и проверено 10.08.2026; все шесть продуктовых решений подтверждены**. Документ описывает
расширение исходной модели, в которой каждый ход обязательно содержал реплику, добавлял два цветовых очка и
рассчитывал восторг по общим правилам.

## 1. Термины и границы фичи

- **Обычный ход игрока** — реплика выбрана и произнесена; действуют текущие правила цветов и восторга.
- **Ход ИИ** — ИИ в самой игре самостоятельно выбрал реплику; реплика известна пользователю и записывается в
  «Суфлёр» постфактум.
- **Непроизнесённая реплика** — игрок пропустил реплику; выбранной реплики нет.
- **Ход** — один из 16 временных слотов пьесы. Любой из трёх исходов расходует ровно один ход.
- **Расчётный восторг** — бонус, который обычная произнесённая реплика получила бы по правилам общего цвета и
  баланса.
- **Фактическое изменение восторга** — изменение счётчика восторга после применения типа хода.

За рамками минимальной версии: прогноз конкретных будущих ходов ИИ, автоматическое распознавание состава группы и
автоматический импорт событий из игры.

## 2. Таблица переходов состояния

| Исход хода | Реплика обязательна | Ход из 16 расходуется | Цветовые очки | Восторг | «Предыдущая реплика» для следующего хода |
| --- | --- | --- | --- | --- | --- |
| Обычный ход игрока | да | да | `+2` по текущим правилам | `0…+3` по текущим правилам | выбранная реплика |
| Ход ИИ | да | да | `+2` по текущим правилам | всегда `0` | выбранная ИИ реплика |
| Реплика не произнесена | нет | да | без изменений | `−1`, но не ниже `0` | последняя фактически произнесённая реплика сохраняется |

Ход ИИ становится предыдущей репликой, потому что реплика была выбрана и изменила цветовой счёт. Пропуск не заменяет
предыдущую фактически произнесённую реплику: следующий обычный ход сравнивается с ней для общего цвета и рассчитывает
бонус баланса по обычным правилам.

## 3. Функциональные требования (ФТ)

### Модель и расчёт

**ФТ-01. Тип исхода хода.** Система должна хранить исход каждого хода независимо от текущего способа ввода
(`вижу 3 варианта` / `вижу только выбор`). Минимальный набор исходов: обычный ход игрока, ход ИИ, непрознесённая
реплика. Существующее поле способа ввода нельзя переиспользовать как тип исхода.

**ФТ-02. Расход хода.** Каждый записанный исход увеличивает номер хода на один. После 16 исходов пьеса завершается и
новые исходы нельзя записать без отмены последнего хода или начала новой пьесы.

**ФТ-03. Обычный ход.** Все существующие правила обычного хода сохраняются без изменений: валидная реплика добавляет
два цветовых очка, а восторг рассчитывается по общему цвету и балансу. Первая обычная реплика в первом ходу по-прежнему
даёт `0` восторга.

**ФТ-04. Ход ИИ.** Для хода ИИ требуется валидная выбранная реплика. Она нормализуется по текущим правилам ввода,
добавляет обычный цветовой вклад и становится предыдущей репликой. Фактическое изменение восторга равно `0`, даже
если расчёт общего цвета и/или баланса дал бы `+1…+3`.

**ФТ-05. Непроизнесённая реплика.** Такой ход записывается без реплики, не меняет ни один цветовой счёт и уменьшает
восторг на `1`, но не ниже `0`: `В := max(0, В − 1)`. Пустой цветовой вклад не должен создавать бонус равенства.
Пропуск сохраняет последнюю фактически произнесённую реплику. Следующий произнесённый ход использует её для проверки
общего цвета и рассчитывает бонус баланса по обычным правилам.

**ФТ-06. Разделение расчётного и фактического эффекта.** Итоговый восторг, сумма изменений по истории и проверка
победы должны использовать фактическое изменение: обычный ход — рассчитанное значение, ИИ — `0`, пропуск — `−1` при
положительном восторге и `0` при нулевом.
Если расчётный эффект ИИ сохраняется для диагностики, он должен называться отдельно и не попадать в итоговую сумму.

**ФТ-07. Последовательности смешанных ходов.** Состояние после любого смешения обычных, ИИ- и пропущенных ходов
должно полностью и детерминированно пересчитываться из истории. В частности, цветовой вклад ИИ участвует во всех
последующих проверках баланса.

**ФТ-08. Отмена.** «Отменить последний ход» должна атомарно отменять все эффекты последнего исхода:

- для ИИ — номер хода, цветовой вклад и смену предыдущей реплики;
- для пропуска — номер хода и штраф восторга; последняя фактически произнесённая реплика определяется оставшейся
  историей;
- для обычного хода — текущее поведение без изменений.

**ФТ-09. Новая пьеса.** Сброс удаляет все типы ходов и возвращает цвета и восторг в начальное состояние.

### Ввод и отображение

**ФТ-10. Запись хода ИИ.** Пользователь должен иметь явно подписанное действие для записи хода ИИ и поле/выбор его
фактической реплики. Пустая или невалидная реплика не записывает ход и показывает ошибку по существующим правилам
валидации.

**ФТ-11. Запись пропуска.** Пользователь должен иметь отдельное явно подписанное действие «Реплика не произнесена».
Оно не должно требовать фиктивной реплики или выбора цвета. Перед выполнением интерфейс должен запросить подтверждение
и однозначно сообщить эффект: `−1 восторг` (но не ниже `0`), `+0 цветовых очков`, `1 ход`.

**ФТ-12. История.** Для каждого хода история показывает номер, исход, реплику при её наличии, фактическое изменение
восторга со знаком и цветовой вклад. Для пропуска вместо цветных фишек показывается текст «Реплика не произнесена».
Для ИИ нельзя показывать положительный восторг, даже если его реплика образовала общий цвет или баланс.

**ФТ-13. Текущее состояние.** После каждого исхода без перезагрузки обновляются: номер хода, цветовые очки, восторг,
оставшиеся ходы, очки до цели, предыдущая реплика, рекомендации и теоретический максимум.

**ФТ-14. Рекомендации после особого хода.** После уже совершённого хода ИИ рекомендации пересчитываются от его
фактической реплики и изменившихся цветов. Система не прогнозирует реплики ИИ и не выбирает за него. Рекомендации
строятся только для доступных пользователю вариантов обычного хода. После пропуска они строятся от прежних цветов и
последней фактически произнесённой реплики.

**ФТ-15. Завершение и победа.** Пьеса завершается после 16 исходов любого типа. Победа определяется фактическим
восторгом после штрафов: `восторг >= 26`.

**ФТ-16. Диагностический снимок.** Снимок должен однозначно воспроизводить исход каждого хода, отсутствие реплики,
цветовой вклад, фактическое изменение восторга, состояние после хода и проверки целостности. Версия схемы снимка
повышается; старый формат документируется как формат до появления особых исходов.

**ФТ-17. Обратная совместимость.** Истории, созданные до фичи и содержащие только `reply` и существующий способ
ввода, интерпретируются как обычные ходы. Их цветовые очки, восторг и рекомендации не должны измениться.

## 4. Нефункциональные требования (НФТ)

**НФТ-01. Корректность и детерминизм.** Один и тот же валидный список ходов всегда возвращает одинаковое состояние.
Расчёт не изменяет переданную историю. Выполняются инварианты:

- `turnCount = количество элементов истории`;
- цветовой итог равен сумме фактических цветовых вкладов;
- восторг равен последовательному применению фактических изменений с нижней границей `0`;
- цветовые очки не уменьшаются;
- ход ИИ имеет нулевой фактический восторг, пропуск — нулевой цветовой вклад.

**НФТ-02. Регрессия правил.** Все существующие unit- и E2E-сценарии обычных ходов проходят без изменения ожидаемых
результатов. Для изменённой расчётной логики сохраняется установленный проектом порог покрытия не ниже 90% по каждой
метрике.

**НФТ-03. Производительность.** Полный пересчёт истории из 16 ходов не должен быть заметен пользователю. В
автоматическом тесте на CI медиана 1 000 пересчётов смешанной истории должна быть не хуже текущей медианы обычной
истории более чем на 20%. Построение рекомендаций не должно блокировать ввод или отмену хода.

**НФТ-04. Доступность.** Новые действия доступны с клавиатуры, имеют различимые accessible name, видимый фокус и не
опираются только на цвет. Изменение восторга и ошибка валидации объявляются скринридеру. Контраст сохраняется на уровне
WCAG 2.1 AA в светлой и тёмной темах.

**НФТ-05. Адаптивность.** Элементы записи ИИ и пропуска не создают горизонтальную прокрутку при ширине viewport
`320 px` и не перекрывают существующие действия при desktop-ширине `1280 px`.

**НФТ-06. Автономность и совместимость.** Production-результат остаётся одним автономным HTML-файлом и работает в
поддерживаемом проектом Chromium без сети. Новая фича не ослабляет CSP.

**НФТ-07. Диагностируемость и приватность.** Снимок содержит достаточно данных для воспроизведения смешанной партии,
но по-прежнему исключает query-параметры и fragment URL и не добавляет персональные данные.

**НФТ-08. Понятность интерфейса.** В истории и подтверждении действия термины «ход ИИ» и «реплика не произнесена»
используются последовательно. Отрицательное изменение отображается как `−1`, нулевое как `0`, без двусмысленного
`+−1`.

## 5. Критерии готовности

Фича готова к выпуску, если:

1. утверждены решения из раздела 8;
2. реализованы ФТ-01…ФТ-17;
3. пройдены обязательные тест-раны TR-01…TR-06;
4. `pnpm test` завершается успешно;
5. документация правил и диагностического снимка обновлена;
6. нет дефектов Blocker/Critical и открытых Major-дефектов в новой логике.

## 6. Тестовые данные

Сокращения: `P(СС)` — обычный ход игрока, `AI(СС)` — ход ИИ, `MISS` — реплика не произнесена. Цвета в ожидаемом
результате указаны как `С–З–К`.

### Базовые последовательности

| ID | История | Проверяемое состояние |
| --- | --- | --- |
| D-01 | `P(СС), AI(СС), P(СС)` | после ходов: `2–0–0 / В=0`; `4–0–0 / В=0`; `6–0–0 / В=1`; ИИ стал предыдущей репликой |
| D-02 | `P(СС), P(ЗК), AI(ЗК), P(ЗК)` | на ходе ИИ создаётся расчётный `+3`, но фактический `0`; после ИИ `2–2–2 / В=0`; последний ход даёт `+2`, итог `2` |
| D-03 | `P(СС), P(СС), MISS, P(СС)` | состояния восторга: `0, 1, 0, 1`; после `MISS` цвета остаются `4–0–0`, последняя `СС` получает `+1` за общий цвет |
| D-04 | `P(СС), P(КК), P(ЗЗ), MISS` | до пропуска `2–2–2 / В=3`; после пропуска `2–2–2 / В=2` |
| D-05 | `P(СС), P(СС), MISS, MISS` | цвета `4–0–0`, восторг снижается до `0` и не уходит в минус; предыдущей остаётся последняя `СС` |
| D-06 | 16 исходов с обычными, ИИ и `MISS` | завершение ровно после 16-го элемента истории независимо от состава |

### TR-05 — Регрессия

1. Выполнить `pnpm test`.
2. Повторить существующие сценарии: обычный анонимный ход и отмена, расчёт трёх вариантов, 16 обычных реплик,
   победная цепочка, обе темы, скачивание snapshot.
3. Сравнить для набора прежних обычных историй: цвета, восторг каждого хода, `projectedAudience`, лучшие варианты и
   итог идеального маршрута до и после изменения.
4. Проверить кириллические/латинские буквы, регистр, перестановку букв двухцветной реплики и сообщения валидации.

### TR-06 — Нефункциональный прогон

| TC | Метод | Критерий прохождения |
| --- | --- | --- |
| NFT-01 | 1 000 пересчётов 16 смешанных ходов и такой же baseline обычных | медиана смешанного набора не хуже baseline более чем на 20% |
| NFT-02 | viewport `320×568`, `768×1024`, `1280×720` | нет горизонтального скролла/перекрытий; действия и история читаемы |
| NFT-03 | клавиатура + accessibility tree в обеих темах | все действия доступны; имена уникальны; фокус виден; `−1` не передан только цветом |
| NFT-04 | production build + CSP/autonomy checks | один автономный HTML, без `unsafe-inline`, функциональность работает offline |
| NFT-05 | snapshot с query и fragment | приватные части URL отсутствуют; новый исход и все его эффекты присутствуют |
| NFT-06 | coverage report | statements, branches, functions и lines — каждая метрика не ниже 90% |

## 8. Продуктовые решения

- **Q-01. Нижняя граница восторга:** восторг не может быть отрицательным; штраф применяется как
  `В := max(0, В − 1)`.
- **Q-02. Общий цвет после пропуска:** пропуск не заменяет предыдущую фактически произнесённую реплику. Например, в
  последовательности `СС → пропуск → СС` последняя `СС` получает `+1` за общий цвет.
- **Q-03. Баланс после пропуска:** следующий произнесённый ход рассчитывает баланс как обычно. Например, после
  `С=2, З=0, К=0 → пропуск → КК` реплика `КК` получает `+1` за равенство синего и красного.
- **Q-04. Запись хода ИИ:** пользователь вводит уже увиденную в игре фактическую реплику ИИ.
- **Q-05. Прогноз ИИ:** система не прогнозирует реплики ИИ. После хода она только учитывает фактический результат.
- **Q-06. Подтверждение штрафа:** перед записью непрознесённой реплики обязательно запрашивается подтверждение.
